1. SYSTEM OVERVIEW & ARCHITECTURE
================================================================================
DrainMind v2.0 is a full-stack, local computer vision web application engineered
for municipal storm-water infrastructure management, drainage obstruction
detection, and urban flood risk prevention.

KEY ARCHITECTURAL HIGHLIGHTS:
- Drain Vision Intelligence Ensemble: Fuses deep-learning object detection
  (Ultralytics YOLOv8) with multi-cue computer vision algorithms (LAB/HSV color
  clustering, texture entropy, and edge geometry) to detect silt mounds,
  floating garbage, standing water pools, and structural concrete cracks.
- Stateful Persistence Architecture: Inspection outcomes and video keyframes
  survive web application reruns and commit directly into a local SQLite
  database with foreign-key referential integrity.
- Real-Time Command Center: Instant synchronization between field captures,
  dashboard KPI metrics, deterioration trend alarms, and audit logs.
- Automated Maintenance Dispatch: Generates municipal work orders and printable
  PDF/CSV dossiers with a single click.

2. QUICK START & EXECUTION
================================================================================
PREREQUISITES:
- Operating System: Windows 10/11, macOS, or Linux.
- Python: Version 3.10+ (tested and verified on Python 3.12 / 3.13).
- Dependencies: Streamlit, OpenCV, Ultralytics, FPDF2, Plotly, Pandas.

LAUNCH INSTRUCTIONS:
1. Open PowerShell or Command Prompt.
2. Navigate to the DrainMind repository root:
     cd D:\DrainMind
3. Launch the application server:
     python -m streamlit run app.py --server.port 8501
4. Open your browser and navigate to:
     http://localhost:8501

RUNNING THE AUTOMATED TEST SUITE:
To verify all 43 automated unit and integration tests across vision, database,
and scoring modules:
     python -m pytest tests/ -v

5. COMPUTER VISION & RISK SCORING FORMULAS
================================================================================
PRIORITY SCORE EQUATION:
The composite Priority Risk Score (0 to 100) is calculated as:

   Risk Score = (W_D * Debris_Coverage_Pct)
              + (W_W * Water_Level_Pct)
              + (W_T * Trend_Delta_Pct)

Where:
- Debris_Coverage_Pct: Percentage of the central channel ROI blocked by silt,
  sediment, or debris (0 to 100%).
- Water_Level_Pct: Percentage of ROI indicating stagnant water or flooding (0 to 100%).
- Trend_Delta_Pct: Increase in blockage compared to previous inspection (0 to 100%).
- W_D, W_W, W_T: Configured weights (Defaults: 0.50, 0.30, 0.20, normalized to 1.0).

SEVERITY THRESHOLDS:
- 0.0  to 29.9  --> [ LOWER PRIORITY ]       Normal flow; standard maintenance.
- 30.0 to 49.9  --> [ MONITOR ]              Moderate silt buildup; monitor closely.
- 50.0 to 69.9  --> [ INSPECTION RECOMMENDED] Significant blockage; dispatch crew.
- 70.0 to 100.0 --> [ HIGH PRIORITY ]        Severe obstruction; emergency clearing!

6. LOCAL SQLITE DATABASE & STORAGE LAYOUT
================================================================================
All data is stored locally on disk without third-party cloud dependencies:
- Database File: `D:\DrainMind\data\drainmind.db`
- Annotated Images: `D:\DrainMind\outputs\annotated\`
- Raw Images: `D:\DrainMind\data\raw\`
- Reports Output: `D:\DrainMind\outputs\reports\`
- User Settings: `D:\DrainMind\configs\user_settings.yaml`

DATABASE TABLES:
1. `locations`: Registered drain catchments, codes, and landmarks.
2. `inspections`: Individual inspection sessions, timestamps, and model backend info.
3. `observations`: Calculated metrics (coverage %, water %, priority score, category).
4. `detections`: Individual defect bounding boxes (class, confidence, x1, y1, x2, y2).
5. `artifacts`: Filepaths to saved annotated images, raw inputs, and video keyframes.

7. TROUBLESHOOTING & FAQ
================================================================================

Q1: Why was the dashboard empty when I first opened it?
A: A fresh database starts with 0 inspections. You can either perform your first
   inspection in Tab 1/2 or click "⚡ Reset / Populate Demo Data" in the sidebar
   or on the Overview page to load 8 sample field inspections immediately.

Q2: How do I test the application if I don't have a drain image or video?
A: Both inspection workspaces include built-in test generators:
   - In Image Inspection: Select "🖼 Test Sample Image" and choose a scenario.
   - In Video Analysis: Go to "🎬 Generate Test Drain Video" and click
     "Generate Simulated Drain Crawler Video".

Q3: How do I use my own fine-tuned YOLO model?
A: Place your trained `.pt` weights file in the `models/` folder, open Tab 6
   (Settings), enter the path in "Custom Model Weights Path", and click
   "Save & Synchronize Settings".

Q4: What if port 8501 is already running?
A: You can start the server on an alternate port:
   python -m streamlit run app.py --server.port 8502
